# Task Context Checklist

Before coding, answer:

- What user or business outcome is required?
- Which existing files implement the current behavior?
- Which tests describe the expected behavior?
- Which database tables/migrations are involved?
- Which routes, services, repositories, or components are involved?
- Which authorization and validation rules apply?
- Which accepted ADRs constrain the solution?
- Is the change backward compatible?
- What telemetry, logging, or audit event is required?
- Which documentation must change?

If an answer is unknown, inspect the repository rather than guessing.
